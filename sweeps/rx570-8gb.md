# RX 570 8 GB (Polaris, Vulkan, Windows 10)

An RX 570 8 GB (Polaris), an older card well below the README's stated Radeon floor (RX 6600), on Windows 10 with a host CPU that has no AVX. Same method as the other cards: the PrismML fork release, `llama-bench` with the CONTRIBUTING flags, served VRAM from the serve line's window. All numbers are from runs on this machine on 2026-10-11.

## Served VRAM

7,971 MiB in use with the lean file loaded at 32,768 context (8 GB tier, MTP head on, `-ub 256`). 1,035 MiB was already in use before the server started, because this card drives a monitor. The reading comes from the speed-check script, not `nvidia-smi`.

## Anything odd

With speculation off, a server run of the same lean file at the serve line's flags decoded at 0.73 tok/s at 32,768 context and 1.27 tok/s at 2,048 context, while `llama-bench` decodes the same file at 3.8 tok/s, and neither `-ub 256` nor the context size explains the whole gap (I did not find what does).

## Extra data from the speed-check script

- With the MTP head: median 5.0 tok/s (5.0 / 5.0 / 5.0 over three runs), 885 of 1,296 drafts accepted. Without it: 0.7 tok/s on all three runs. Greedy text was identical with and without the head.
- Thermals (HWiNFO log over the 48-minute run): GPU peak 74 C, core clock 1340 MHz and memory clock 1750 MHz flat, no throttling, no memory errors, fans about 20 percent.
- The script's hidden `Start-Process` launch failed with "Access is denied" at `bonsai2.ps1` line 145; starting the server by hand with the printed command worked.
